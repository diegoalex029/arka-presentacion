HU1 — Registro de productos

Como administrador,
quiero registrar productos en el sistema,
para tener un catálogo disponible para los clientes.

Criterios de aceptación​

  • El producto debe tener nombre, descripción, precio, stock y categoría
  • Los campos nombre, precio, stock y categoría son requeridos
  • El precio debe ser mayor a cero
  • El stock no puede ser negativo
  • El sistema retorna mensaje de confirmación al registrar exitosamente

Endpoint​

POST http://localhost:8081/api/products/register
Content-Type: application/json

{
  "name": "iPhone 15 Pro",
  "description": "Smartphone Apple con chip A17 Pro",
  "price": 4500000.00,
  "stock": 15,
  "category": "SMARTPHONE"
}

Respuesta exitosa — 200 OK​

{
  "id": 1,
  "name": "iPhone 15 Pro",
  "message": "Product registered successfully"
}

Respuesta cuando falta un campo — 400 Bad Request​

{
  "status": 400,
  "error": "BAD_REQUEST",
  "message": "name must not be blank"
}

Validación de campos requeridos​

La validación se implementó directamente en el constructor del record DTO. Cuando Jackson deserializa el JSON, lanza IllegalArgumentException automáticamente si algún campo no cumple la validación:

public record RegisterProductRequestDTO(
        String name,
        String description,
        BigDecimal price,
        Integer stock,
        String category
) {
    public RegisterProductRequestDTO {
        if (name == null || name.isBlank())
            throw new IllegalArgumentException("name must not be blank");
        if (price == null || price.compareTo(BigDecimal.ZERO) <= 0)
            throw new IllegalArgumentException("price must be positive");
        if (stock == null || stock < 0)
            throw new IllegalArgumentException("stock must be >= 0");
        if (category == null || category.isBlank())
            throw new IllegalArgumentException("category must not be blank");
    }
}

Manejo de excepciones​

El GlobalExceptionHandler centraliza el manejo de errores y mapea cada excepción a su código HTTP:

@ExceptionHandler(IllegalArgumentException.class)
public ResponseEntity<ApiErrorResponse> handleIllegalArgument(
        IllegalArgumentException ex, ServerHttpRequest request) {
    return ResponseEntity
            .status(HttpStatus.BAD_REQUEST)  // 400
            .body(new ApiErrorResponse(...));
}

Persistencia sin JPA — R2DBC​

Sin JPA no hay @Entity ni cascade. Cada operación de persistencia es explícita y reactiva:

public Mono<Product> save(Product product) {
    return repository.save(ProductMapper.toData(product))
            .map(ProductMapper::toDomain);
}

La entidad de base de datos es un simple record con @Table:

@Data
@Table(name = "products")
public class ProductData {
    @Id
    private Integer id;
    private String name;
    private BigDecimal price;
    private Integer stock;
    private String category;
}
